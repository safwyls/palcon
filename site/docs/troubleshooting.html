Troubleshooting

Each of these has shown up in real deployments. If yours isn't here, open an issue with the container logs.

"unable to open database file: out of memory (14)" on startup

SQLite's error 14 is SQLITE_CANTOPEN; the "out of memory" wording is a generic driver string, not a real memory problem. The container can't write to /data. Check ownership of the host dataset with ls -la — either set user: to match its owning uid/gid, or chmod 775 the directory so the container's group can write.

Player pals shows "Set up save file reading"

The server has no Save path set, or the path doesn't point at a directory containing Level.sav. Remember it's the path inside the container (/saves/myserver), not the host path. See Reading save files.

Power controls don't appear

Either DOCKER_HOST isn't set on the Palcon container, or the server has no Container name. If both are set and actions fail with a permission error, the proxy needs CONTAINERS=1 and POST=1. See Power control.

TrueNAS reports the container as "crashed" after a stop

Palworld images generally ignore SIGTERM, so a forced stop records exit code 137, which TrueNAS labels "crashed". Palcon avoids this by asking the game to exit on its own — if you still see 137, the game was already unresponsive when you pressed stop. Explained in How stopping works.

The container comes back up on its own after a stop

Check the Palworld app's restart policy — TrueNAS may be reviving it independently of Docker's own bookkeeping.

Metrics, settings or charts are missing

Those features are REST-only; Palworld's RCON command set has no equivalent. Enable the REST API in PalWorldSettings.ini — see the deploy guide.
