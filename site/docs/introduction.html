Introduction

Palcon is a self-hosted web console for Palworld dedicated servers — a single Go binary with the React frontend embedded, built to run as a Docker container next to your game server. TrueNAS Scale is the first-class target, but any Linux box with Docker works the same.

What you get

  • Watch — a live dashboard with metrics and players online, performance charts (FPS, frame time, player count over 7 days), a live world map with guild bases and point-of-interest layers, every player's pals with IVs and passives, their inventories drawn slot by slot, paldex completion and server records, and a join/leave activity board with playtime rankings.
  • Manage — start/stop/restart, a PalWorldSettings.ini editor, SteamCMD cache repair and updates with a live transcript, scheduled zip backups of the save, in-game broadcasts, per-user permissions with an admin audit trail, and per-server visibility switches so a view — or one player's pals, bags or position — can be kept private.
  • Automate — scheduled restarts with in-game warnings, a crash watchdog with a three-strikes stand-down, Discord notifications, and an opt-in public status page.
  • Plan — breeding calculators that know what's actually in your server's boxes: child species, reverse lookup, shortest breeding routes and passive-inheritance odds. A team builder that ranks the save's pals against any tower boss, raid or field boss — element edges, real stats and partner-skill synergies — and fills your party with a reason on every pick. And a base crew planner: each base's work-suitability board, night coverage, sick and idle pals, and upgrade picks from the guild's boxes.

How it connects

Palcon talks to the game server over its REST API (port 8212) when available and falls back to Source RCON (port 25575) automatically. Metrics, the settings editor and the performance charts are REST-only — Palworld's RCON command set has no equivalent — so enabling REST is worth the one-line config change.

Everything beyond commands — player pals, inventories, guilds, paldex, map positions while the server is offline — comes from reading the world save file directly. See Reading save files for how that works and why it can never write.

Three rules the design never breaks

Saves are read-only, structurally. The save mount is read-only and the newer save format is unwrapped with a decompress-only library. There is no code path that can write a save file.

No Docker socket. Power control goes through a scoped proxy that allows exactly inspect, start, stop and restart. A compromised Palcon can bounce your game server — that's the worst case.

Your data stays home. One SQLite file on your own disk, credentials encrypted at rest, and no outbound connections except a Discord webhook you explicitly configure.
