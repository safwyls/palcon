Automation & alerts

The features you stop noticing because things just keep working — all configured per server on its Automation tab.

Save backups

Zip snapshots of the (read-only) save mount into Palcon's data dataset on a schedule, with count-based retention, mid-write detection and skip-when-unchanged. Browse, download and delete from the dashboard.

Restores are manual by design: stop the server, unpack a snapshot over the save, start it again. An automated restore verb would break the read-only guarantee that everything else relies on.

Scheduled restarts

Per-server restart schedules (weekdays + time) with in-game warning broadcasts at configurable lead times; the world is saved before every restart. The restart itself goes through whoever owns the game process — a supervisor-mode agent first, docker power control as the fallback, exactly like the manual power buttons; without either, the game is asked to shut down and the container's restart policy brings it back.

Crash watchdog

Optionally revives a container that exits with an error, with a cooldown and a three-strikes stand-down — a crash loop gets a human instead of a fourth restart. Clean stops are never revived.

On a server with a supervisor-mode agent the watchdog stands down automatically: the supervisor already revives crashes with backoff, and the container never exits just because the game did, so the card reports the job as covered instead of offering a switch that would do nothing.

Discord notifications

A per-server Discord webhook (encrypted at rest, never sent back to the browser) for server down/back-online, player joins and leaves, and scheduled-restart notices — each individually toggleable.

Public status page

An opt-in, unauthenticated page behind an unguessable link: online/offline, player count, next scheduled restart. Served entirely from Palcon's own data, so visitors never touch the game server, and no player names or addresses appear.
