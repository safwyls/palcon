Deploy with Docker

Nothing beyond the compose examples is TrueNAS-specific. Any Linux host with Docker works identically — use your own uid:gid in place of TrueNAS's 568:568.

Quick run

shell
docker pull ghcr.io/safwyls/palcon:latest
docker run -p 8080:8080 \
  -v $(pwd)/data:/data \
  -e JWT_SECRET=... -e ENCRYPTION_KEY=<32 chars> -e ADMIN_PASSWORD=... \
  ghcr.io/safwyls/palcon:latest

Or docker compose up using the bundled docker-compose.yml, which already includes the socket proxy and annotated volume mounts. The full annotated spec is on the TrueNAS page — drop the user: line or set your own uid/gid.

Image tags

TagMeaning
latesttip of main
betathe beta branch — a test channel that real deployments can pull without touching latest
X.Y.Z / X.Ypublished when a vX.Y.Z git tag is pushed — pin these for deliberate updates
sha-<short-sha>every commit, for reproducing an exact build

The same scheme applies to ghcr.io/safwyls/palagent, so a compose stack can pin one channel across the pair.

Windows

Docker Desktop/WSL2 works with the usual caveats: keep the data volume inside the Linux filesystem, and expect UDP game traffic through Docker Desktop's port forwarding to be fine for friends, less so for a large public server.
