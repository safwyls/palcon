First login & your first server

Open http://<host>:30801 (or whatever port you published) and sign in with ADMIN_USERNAME / ADMIN_PASSWORD. Those variables bootstrap a single admin on the first run only — after that, accounts live in the database and the Users screen manages them.

Add a server

Add server in the left rail registers an existing Palworld server. Fill in host, ports and passwords from your PalWorldSettings.ini. Two optional fields unlock the extras:

  • Container name — the Palworld container's name on the same host, enabling Start/Stop/Restart on the dashboard. Needs the docker-socket-proxy configured.
  • Save path — the path inside Palcon's container (e.g. /saves/myserver, not the host path), enabling Player pals, Guilds and Paldex. See Reading save files.

Or create a new server from the dashboard

The New server wizard (behind the add-server dialog) goes further than registering: it generates a fully wired server row — host, ports, admin password, agent token — and emits a ready-to-deploy supervisor-mode stack file with copy and download buttons. Paste it into a Custom App and the agent installs the game on first boot, coming up already connected.

With the optional provisioner configured, the wizard deploys the stack itself — one click, watch the install stream on the server's card. Existing palagent containers on the host can also be discovered and re-adopted, secrets recovered automatically. Removal is symmetric: the remove-server dialog can optionally destroy the deployed container too — the world data always stays on disk.

Give your players accounts

The Users icon at the bottom of the rail (admins only) creates accounts for other players. Everyone signed in can view everything; grant each account only the actions they need — giving a player just Power lets them start the server in the morning without any other administrative access. Details in Users & permissions.
